## 1. 环境基线

| 项 | 要求 | 说明 |
|---|---|---|
| Python | ≥ 3.11（本机 3.14.2 实测） | 不用 3.12+ 独占语法，保证 3.11 可跑 |
| 运行时依赖 | **零第三方依赖**（ADR-001） | `pyproject.toml` 的 `dependencies = []` |
| 开发依赖 | `pytest>=8` | `pip install -e ".[dev]"` 或直接用本机 pytest |
| 操作系统 | Windows / macOS / Linux | 只允许 `pathlib`、`os.replace`、`O_CREAT\|O_EXCL`，禁止 `fcntl` |
| 编码 | 全仓库 UTF-8（`encoding="utf-8"`、`newline="\n"`） | Windows 下禁止依赖系统代码页 |
| 网络 | mock 模式零网络；live 模式只连 `LLM_BASE_URL` | 不访问其它域名，不装包、不 clone |
| Shell | 不拼 shell 字符串；子进程一律传 list | `subprocess.run([sys.executable, ...])` |

### 1.1 安装与自检

```powershell
cd projects\p2-ai-native-platform
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"

python -m pytest -q            # 全量测试（mock，离线）
python -m specflow doctor      # 环境自检
```

> 若不想建 venv：本机全局已有 `pytest`，直接 `python -m pytest -q` 也可，但**提交前必须保证无第三方 import**。

### 1.2 live 模型接入（面试演示用）

1. 复制配置：`Copy-Item .env.example .env`。
2. 填 4 个字段（`.env` 已被 `.gitignore` 忽略，**不要提交 Key**）：

```dotenv
LLM_MODE=live
# 默认（已实测）：阿里云百炼 · 千问 qwen-plus
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_API_KEY=sk-...
LLM_MODEL=qwen-plus
# 备选：DeepSeek → https://api.deepseek.com/v1 + deepseek-chat
```

3. 验证连通（不跑全流程，只花一次小请求）：

```powershell
python -m specflow doctor            # 应显示 llm_mode=live, api_key=set
python -m specflow run "/explore"    # 单阶段冒烟；看 .spec/traces/stage-*.jsonl 的 llm 事件（含 usage）
```

4. 三档运行口径：

| 模式 | 配置 | 用途 | 时延口径 |
|---|---|---|---|
| `mock` | `LLM_MODE=mock` | 测试、离线验收、CI | 全流程 ≤90s（实测 7.5s） |
| `live` | `LLM_MODE=live` + Key | 面试现场真实模型演示 | 单阶段 10–40s，全流程 2–8min（qwen-plus 实测 145.7s），不承诺 90s |
| `auto` | 默认 | 有 Key 走 live，无 Key 自动 mock | 取决于解析结果 |

> 2026-10-30 实测：百炼 `qwen-plus` 全流程 145.7s（复跑 165.6s；9 次模型调用 = 阶段 6 + TDD 3；约 31,938 tokens；TDD 首轮 3/3，QA 三段 pass，回灌 R-06~R-08）。百炼对 `sk-ws-...` 形式的 workspace token 也有效；401 `invalid_api_key` 时先在控制台重新生成 Key。额度以控制台为准，一次全流程约 9 次调用 / 3.2 万 tokens，通常远小于新用户免费额度。

**演示建议**：先 `LLM_CACHE=1` 跑一遍完整流程把真实响应缓存到 `.spec/cache/llm/`，现场断网也能回放（trace 里 `cached=true` 会明示，不冒充实时）；有网则 `LLM_CACHE=0` 跑实时。

## 2. 目录与模块边界

- 只允许按 [07 §1](./07-详细设计与接口契约.md#1-包结构与依赖方向) 的方向 import；**反向 import 视为缺陷**。
- 每个包必须有 `__init__.py`；`__init__.py` 只做轻量导出，禁止副作用（不读文件、不建目录、不联网）。
- 产物模板放 `specflow/templates/`，阶段契约放 `skills/`，演示仓库放 `fixtures/demo-repo/`；运行期产物只写目标仓库的 `.spec/` 与仓库根 4 个文件（`AGENTS.md`/`domain.md`/`index.md`/`templates/`）。
- 共享文件（`config.py`、`errors.py`、`util.py`、`jsonschema.py`、`cli.py`、`engine/runner.py`、`tests/conftest.py`、`docs/07`）只有 Lead 可改；并行开发时只改自己任务声明的写范围。

## 3. 代码规范

| 项 | 约定 |
|---|---|
| 类型 | 公共函数必须带类型标注；模块头 `from __future__ import annotations`；用 `X | None` 而非 `Optional[X]` |
| 文档字符串 | 每个模块一句中文 docstring；公共类/函数写用途 + 关键约束；内部函数可省略 |
| 命名 | 模块/函数/变量 snake_case，类 PascalCase，常量 UPPER_SNAKE；产物名/命令名用 kebab-case 字面量 |
| 异常 | 业务失败用 `specflow.errors` 中的类型；不要 `except Exception: pass`；需要降级时必须写 trace |
| 返回值 | 不返回 `None` 掩盖错误；「没有」用 `load_or_none` 这类显式方法 |
| 副作用 | 模块 import 期零副作用；写文件集中到 store/indexer/util |
| 时间 | 一律 `util.now_iso()`（带时区），禁止 `datetime.now()` 裸用 |
| 随机 | 禁止 `random`；需要 id 用 `util.short_id`/`new_artifact_id` |
| 日志 | 不引 logging 配置；CLI 输出走 stdout（人读），诊断/错误走 stderr；结构化信息写 trace JSONL |
| 隐私 | 代码、fixture、mock 数据不含真实公司名/内网地址/个人信息；统一用 `lin.xu` 等虚构身份 |

### 3.1 文件与路径

- 所有路径用 `pathlib.Path`；展示给用户时用 `path.as_posix()` 或相对路径。
- 写文本必须 `encoding="utf-8"`；写 Markdown 固定 `\n` 换行（`newline="\n"`），避免 Windows 下 `\r\n` 破坏 hash。
- 覆盖写必须走 `util.atomic_write_text`（tmp + `os.replace`）；JSON 用 `util.dump_json`。
- 备份目录 `.spec/backup/` 只由 `ArtifactStore.save` 写入；禁止手写。
- 文件锁只用 `O_CREAT|O_EXCL` 语义（`artifacts/lock.py`）；Hook 进程只读不加锁。

### 3.2 子进程

- 一律 `subprocess.run([...], cwd=..., text=True, capture_output=True, timeout=...)`。
- 超时/非零退出不抛裸异常，转成结构化结果（Verifier 的 `failure_items`）。
- 不调用 `bash -c`/`powershell -Command` 包装被测命令，保证三平台一致。

## 4. 数据与协议规范

- `.spec/state.json`、`.spec/index/artifacts.json`、trace JSONL、lock JSON 的字段以 07 §3 为准，**新增字段只能追加，不能改名**。
- 产物 front-matter 只放元数据；列表/结构化数据放正文末尾 `## 附录：结构化数据` 的 ```` ```json ```` 块（ADR-003）。
- 退出码：`0` 成功、`2` 门控/规则硬阻断、`3` 需人工、`1` 运行错误（07 §2.2）。禁止用 `sys.exit(-1)` 或其它码。
- Hook stdout 必须是**单行合法 JSON**（`ensure_ascii=False`），stderr 单行 ≤200 字；调试信息不得混入 stdout。
- 时间字段统一 `2026-10-30T20:14:03+08:00` 格式；hash 统一正文 sha256 前 12 位。

## 5. 测试规范

| 层级 | 目录 | 规则 |
|---|---|---|
| unit | `tests/unit/` | 纯函数/单模块，毫秒级，不依赖 fixture 仓库；LLM 必须 mock |
| contract | `tests/contract/` | hook 的 stdin/stdout 协议，真子进程，断言 JSON 结构 + 退出码 |
| e2e | `tests/e2e/` | 临时仓库副本跑多阶段；mock LLM；断言产物字段与状态机 |

- 每个测试在 `tmp_path` 里建仓库（`tests/conftest.py` 的 `repo`/`inited_repo` fixture），**禁止写 `fixtures/demo-repo`**。
- 断言产物时用 `ArtifactStore.load`/附录 JSON，不硬编码整段 Markdown。
- 时间不敏感断言：比较「事件顺序」「轮次」「状态枚举」；需要固定时间时 monkeypatch `specflow.util.now_iso`。
- 离线断言：`tests/e2e/test_flow.py::test_offline_full_flow` 用 monkeypatch 让 `socket.socket` 抛错，全流程仍通过（AC-21）。
- 新增行为必须同时加测试；bug 修复先写失败用例。
- 命令：`python -m pytest -q`；局部：`python -m pytest tests/unit/test_gate.py -q`。

## 6. Git 与提交规范

- 分支：`main` 保持可跑；功能分支 `feat/p2-<module>`；一次提交只做一件事。
- 提交信息：`feat(specflow): 阶段门控`、`fix(hooks): 修复 UserPromptSubmit 退出码`、`docs(p2): 07 契约补附录格式`、`test(tdd): 补 AC-17 上限用例`。
- 不提交：`.env`、`.spec/`（目标仓库运行期产物）、`.demo/`、`.venv/`、`__pycache__/`、`.pytest_cache/`。
- 提交前检查：`git diff --stat`（无意外文件）、`python -m pytest -q`（全绿）、`python -m specflow doctor`（无 FAIL）。

## 7. 调试手册

| 现象 | 先看什么 | 处理 |
|---|---|---|
| 阶段被 block | `reason`/`missing`/`howto`；`.spec/state.json` 的 gates | 按 howto 补命令；连续 3 次失败是防抖，不会自动重试 |
| 产物 hash 不一致（tampered） | `state.json` 的 hash vs 文件正文 | `specflow restore <name>` 回滚，或 `gate revise` 出新版本 |
| hook 无输出/超时 | `echo '{}' \| python -m specflow hook SessionStart`；`.spec/traces/hooks-*.jsonl` | 默认 fail-open；用 `SPECFLOW_STRICT_HOOKS=1` 复现 fail-closed |
| live 模型 401/超时 | `.env` 的 base_url/key/model；`doctor` | 先切 `LLM_MODE=mock` 保证流程可演示，再修 Key |
| TDD 一直失败 | `tdd-report.jsonl` 的 failure_items；测试文件内容 | 手动 `python -m pytest -q` 复现；超 3 轮会转 needs_human |
| 写锁残留 | `.spec/locks/*.lock` 的 owner/pid/expire_at | 过期自动抢占；未过期 `specflow unlock <name> --force` |
| 演示环境脏 | `.demo/` 可随时删；`.spec/` 可重建 | `python scripts/demo.py --reset` 从 fixture 重新初始化 |

## 8. 完成定义（DoD）

一个模块算完成，必须同时满足：

1. 代码按 07 契约实现，无第三方依赖，无反向 import；
2. `python -m pytest -q` 中相关用例全绿，新增行为有测试；
3. 有中文 docstring 与错误提示（提示必须告诉用户「下一步跑什么」）；
4. 产生的 trace/state 字段符合 07；失败路径有降级与记录；
5. 对应文档（07 契约/09 测试矩阵）已同步；README 中的命令能照抄跑通。
