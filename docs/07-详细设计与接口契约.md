**依赖方向（禁止反向 import）**：

```text
config / errors / util / jsonschema          （最底层，无内部依赖）
        ↑
artifacts ← engine.stages/state/gate ← engine.runner → agents → llm
                                     ↘ hooks → artifacts/engine.state
                                     ↘ platforms
cli → engine.runner / hooks.manager / engine.gate / artifacts.*
```

`hooks` 可以 import `artifacts`、`engine.state`、`engine.stages`、`util`；`engine.runner` 可以 import 全部；`artifacts` 不得 import `engine.runner`/`hooks`；`llm` 不得 import `agents`/`engine`。

### 2.1 `specflow/config.py`

```python
@dataclass(frozen=True)
class Settings:
    project_dir: Path          # 目标仓库根（默认 cwd）
    spec_dir: Path             # 默认 <project_dir>/.spec
    llm_mode: str              # live | mock | auto（auto：有 key→live，否则 mock）
    platform_mode: str         # mock | live
    llm_base_url: str          # 默认 https://api.deepseek.com/v1
    llm_api_key: str           # 空串表示无
    llm_model: str             # 默认 deepseek-chat
    llm_temperature: float     # 0.3
    llm_timeout_s: float       # 60
    llm_json_mode: bool        # True
    llm_cache: bool            # False；live 缓存到 .spec/cache/llm/
    owner: str                 # 门控操作人：--as > live SSO whoami > SPECFLOW_OWNER
    strict_hooks: bool         # False
    max_rounds: int            # 3
    gate_repeat_limit: int     # 3
    session_budget: int        # 900
    prompt_budget: int         # 300
    platform_fixture: str|None # None | pipeline-fail | rpc-error

    # 兼容属性（供各模块只读访问）
    artifacts_dir: Path        # .spec/artifacts
    traces_dir: Path           # .spec/traces
    backup_dir: Path           # .spec/backup
    locks_dir: Path            # .spec/locks
    index_dir: Path            # .spec/index
    cache_dir: Path            # .spec/cache/llm
    state_path: Path           # .spec/state.json
    artifacts_index_path: Path # .spec/index/artifacts.json
    skills_dir: Path           # platform_root/skills
    fixture_repo: Path         # platform_root/fixtures/demo-repo
    platform_root: Path        # 包根（specflow/ 的父目录）

    @classmethod
    def load(cls, project_dir: Path|None = None,
             overrides: Mapping[str, Any]|None = None) -> "Settings"
    def with_overrides(self, **kw) -> "Settings"
    @property
    def effective_llm_mode(self) -> str        # auto 解析后的结果
```

**环境变量优先级**：`overrides` > 进程环境变量 > `<project_dir>/.env` > `<platform_root>/.env` > 默认值。
`.env` 解析：`KEY=VALUE`，支持 `#` 整行注释、值两端引号去除；不支持变量展开。

| `LLM_API_KEY` | 空 | 空且 mode=auto → mock |
| `LLM_MODEL` | `deepseek-chat` | |

| `LLM_JSON_MODE` / `LLM_CACHE` | 1 / 0 | |
| `PLATFORM_MODE` | `mock` | mock=本地 JSON；live=HTTP REST 适配层 |

| `PLATFORM_TOKEN` | 空 | live Bearer Token |
| `PLATFORM_TIMEOUT_S` | 10 | live 请求超时（秒） |
| `SPECFLOW_OWNER` | `specflow-user` | 门控默认操作人 |

### 2.2 `specflow/errors.py`

```python
class SpecflowError(Exception):
    exit_code = 1
    def __init__(self, message: str, *, hint: str|None = None): ...

class UsageError(SpecflowError): ...            # 参数错误 → 1
class GateBlocked(SpecflowError):               # → 2
    exit_code = 2
    def __init__(self, message, *, missing: list[str]|None = None,
                 reasons: list[str]|None = None, howto: str|None = None): ...
class NeedsHuman(SpecflowError): exit_code = 3   # 写锁占用/连续门控失败/TDD 超限
class LockBusy(NeedsHuman): ...
class LLMError(SpecflowError): ...
class ArtifactError(SpecflowError): ...
class ArtifactNotFound(ArtifactError): ...
class IllegalTransition(SpecflowError): ...
class HookError(SpecflowError): ...
```

CLI 顶层捕获：`SpecflowError` → 打 `[specflow] ...` 到 stderr，返回其 `exit_code`；未捕获异常 → traceback + `1`。

### 3.1 `.spec/state.json`

```json
{
  "schema_version": 1,
  "stage": "S3",
  "owner": "lin.xu",
  "artifacts": {
    "design.md": {"version": 2, "hash": "9f2c1a7b4d05", "status": "approved",
                  "stage": "S3", "updated_at": "2026-10-30T20:31:40+08:00"}
  },
  "gates": {
    "design":    {"status": "approved", "by": "lin.xu", "note": "选型可接受",

  "gate_failures": {"plan-task": 1},
  "needs_human": false,
  "last_command": "/tech-design",

### 3.6 产物 front-matter（通用字段）

```yaml
---
id: ART-DESIGN-0003
name: design.md
stage: S3
version: 2
status: draft            # draft | reviewed | approved | superseded
owner: lin.xu
created_at: 2026-10-30T20:14:03+08:00
updated_at: 2026-10-30T20:31:40+08:00
source: {type: file, ref: .spec/artifacts/exploration.md}
summary: 用事件表替换轮询，接口保持兼容，回滚靠开关
toc: ["1 选型对比", "2 模块改动", "3 接口变更", "4 风险与回滚"]
hash: 9f2c1a7b4d05
---
```
- YAML 子集：`key: scalar`、`key: [a, b, c]`、`key: {k: v, k2: v2}`；scalar 支持字符串/数字/布尔；字符串不加引号（含 `: ` 或 `,` 时加双引号）。不支持多行/注释/锚点。
- `hash` 在写入时由 `ArtifactStore.save` 依据正文计算并回写；`artifact.hash` 属性实时计算正文 hash（读取时用它校验是否被篡改）。
- `toc` 由正文 `## ` 标题自动生成，调用方可省略。
- 结构化附录：正文末尾可选

````markdown
## 附录：结构化数据

```json
{"requirements": [...]}
```
````
`schema.py` 的强校验读附录；缺失视为字段不全（除非该产物不要求附录）。

## 4. 模块 API 契约

以下签名是实现基线；实现者不得随意改参数顺序/返回类型，需要变更先改本文。

### 4.1 `artifacts/frontmatter.py`

```python
def parse(text: str) -> tuple[dict[str, Any], str]        # (meta, body)；无 front-matter 抛 ArtifactError
def render(meta: Mapping[str, Any], body: str) -> str     # 稳定排序 + 末尾单换行
def generate_toc(body: str) -> list[str]                 # ["1 选型对比", ...]
```

### 4.2 `artifacts/store.py`

```python
@dataclass
class Artifact:
    name: str                 # "design.md"
    path: Path
    meta: dict[str, Any]
    body: str
    @property
    def version(self) -> int
    @property
    def status(self) -> str
    @property
    def hash(self) -> str                        # 正文 sha256[:12]
    def summary(self) -> str
    def sections(self) -> list[str]              # 所有 "## " 标题（去掉前缀序号）
    def has_section(self, title: str) -> bool    # 忽略编号与空格差异
    def section_body(self, title: str) -> str|None
    def appendix(self) -> dict[str, Any]|None    # 解析 ```json 结构化附录，失败返回 None

class ArtifactStore:
    def __init__(self, settings: Settings): ...
    def path_of(self, name: str) -> Path
    def exists(self, name: str) -> bool
    def load(self, name: str) -> Artifact                    # 不存在抛 ArtifactNotFound
    def load_or_none(self, name: str) -> Artifact|None
    def list(self) -> list[Artifact]                         # 按 stage 排序

循环规则：`plan → 写测试 → 写实现 → 跑测试`；失败项回流下一轮计划；`round > max_rounds` → `needs_human` 且保留测试文件；每步追加事件到 `.spec/artifacts/tdd-report.jsonl`。事件行 = `{ts, stage, round, role, event, ...业务字段}`（`ts/stage` 与 §3.4 公共字段一致；`event` 取 `plan_ready/test_written/impl_written/fail/pass/needs_human`，不另设 `step/status` 字段），保证 AC-15 可直接按 `event` 顺序断言。TDDRunner 每轮把 `tdd-plan.md` 保存到 ArtifactStore（meta: `task_id`,`round`；status=draft），`/add` 的 runner 只汇总 `tdd-report.md`。

> 报告类产物的 status 与 verdict 对齐：`tdd-report.md`/`qa-report.md` 在 `verdict=pass` 时 status=`approved`，否则 `draft`；这样下游阶段只需在 SKILL.md 里声明 `requires: [tdd-report.md:approved]` 即可复用同一套机器门。

**演示任务契约（fixture 仓库 T1，mock 与测试共用）**：

## 7. 错误与降级矩阵（实现级）

| 场景 | 行为 | 退出码 |
|---|---|---|
| 上游产物缺失/状态不符/hash 篡改 | `GateBlocked`，打印 `missing`+`howto`，不调 LLM | 2 |
| 人门未批准 | `GateBlocked`（同上） | 2 |
| 连续 3 次门控失败（同一命令） | `NeedsHuman`，提示停止自动重试 | 3 |
| `hook` 处理异常 | 默认 fail-open（allow/continue + trace error）；`SPECFLOW_STRICT_HOOKS=1` → fail-closed | 0/2 |
| LLM 超时/非 2xx | 重试 1 次后 `LLMError`；产物不变；state 仅记录 `last_command` 等运行痕迹，阶段不推进 | 1 |
| LLM JSON 非法 | 纠错重试 1 次；仍失败 `LLMError`（不落盘） | 1 |
| 产物 schema 校验失败 | `ArtifactError`，列出缺失章节/字段，不落盘 | 1 |
| 写锁被占 | `LockBusy`，提示 owner/pid/剩余秒数 | 3 |
| TDD 超 3 轮 | 状态 `needs_human`，测试文件保留，摘要列出失败项 | 3 |
| 子进程（pytest）超时 | 记 `failure_items=[{case:"<pytest>",error:"timeout"}]` | 3 |
| mock 数据缺失 scenario | `UsageError`（暴露 fixture 问题） | 1 |
